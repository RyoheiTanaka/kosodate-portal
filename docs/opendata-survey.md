# つくば市オープンデータの棚卸し（#112 の検討結果）

調査日: **2026-08-28**。掲載中の認可保育所等一覧以外に、このサイトに載せられる
データが市から出ているかを、実ファイルまで開いて確認した記録。

#112 は「気が向いたときに見返すための置き場」として書かれていて、データセット名の
一覧までしか無かった。名前だけでは載せられるかどうか判断できないので、
**件数・座標の有無・ファイル形式・実際の最終更新日**を実測した。

結論だけ先に書くと、**採否を分けたのは座標の有無ではなくファイルの鮮度**だった。
#112 が優先度1位に置いていた病児・病後児保育は、xlsx が3年以上更新されておらず
**現況と食い違う電話番号が入っている**ため不採用にした。

## 調べたこと

- 公開一覧 https://www.city.tsukuba.lg.jp/opendata/10060.html （掲載407件）から
  子育て関連のデータセットを抽出
- 各公開ページから実ファイルのURLを取り、xlsx をダウンロードして列と行数を確認
- ファイルの `Last-Modified` ヘッダで実際の更新日を確認（一覧の「リリース日」は
  データセット登録日で、ファイルの更新日ではない）

再現用のメモは末尾に置いた。

## 判定

#112 の4基準（探すものか／位置情報があるか／継続更新されるか／個別規約が無いか）
に実測値を当てた結果。

### 採用する

| データ | 理由 |
| --- | --- |
| 児童館 / 公設公営・公設民営・民設民営児童クラブ | 座標つき、142件。小学校区つき。主要な3ファイルは2026年に更新されている |
| 地域子育て支援拠点 | 座標つき、19件。実施日・実施時間まである。乳幼児を抱えた層とそのまま重なる |

**公設民営（7件・2024-05更新）だけは古い**が、同じ「児童クラブ」の一部を欠かすほうが
不自然なので、鮮度の但し書きつきで一緒に入れる。

### 条件つきで採用する

| データ | 条件 |
| --- | --- |
| 遊具のある公園（192件） | #184 の「周辺の子育て施設」の件数・距離**だけ**に使う。ファイルが2022年なので、遊具の内訳は載せない（撤去・更新が反映されていない）。公園そのものの位置は動きにくいので件数と距離は成立する |
| 私立幼稚園・認定こども園（14件） | ファイルが2022年。市のページと突き合わせて差分が無いことを確認してから入れる。園数が14なので手検証できる |

### 採用しない

| データ | 理由 |
| --- | --- |
| **病児・病後児保育** | xlsx が2022-11で、ページ（2026-07更新）と**内容が食い違う**。例: さくら学園保育園の電話番号は xlsx が `029-863-0053`、ページは `080-8328-4960`。緊急性の高い情報でこの誤りを載せるのは、載せないより悪い |
| 一時預かり / 認可外保育施設 | PDFのみ。手で転記すると年1回の更新運用に乗らず、転記ミスがそのまま残る |
| つくば市都市公園・緑地一覧 | 座標が無く、遊具のある公園一覧で用は足りる |
| キッズクラブカード交付場所 | 「子育て世帯が実際に探すもの」に当たらない。カードの交付窓口一覧であって施設情報ではない |
| あかちゃんの駅 | 公開ページが404で取得できない |
| 小中学校・幼稚園一覧 | **CC BY-ND（改変禁止）**。他のデータと違いライセンスが別で、DBに取り込んで再構成する使い方ができない |

病児・病後児保育と一時預かりは、**情報としては重要なので市のページへリンクする**
（FAQ からの導線）。データとして持たない、という判断であって、触れないという意味ではない。

## 実装するときに分かっていること

実ファイルを開いて分かった、取り込みスクリプトに効く事実。

- **xlsx にルビが埋まっている。** セルの共有文字列に `<rPh>` が入っていて、素直に
  `<t>` を連結すると「横町127-４ヨコマチ」のようになる。`<rPh>` を落としてから読む
- **住所の表記が揃っていない。** 児童館は `横町127-４`（市名なし）、支援拠点は
  `つくば市流星台６１－１`（全角数字）。既存の `toOaza()`（`scripts/import-nurseries.mjs`）は
  どちらも大字を取り出せるが、`address` にそのまま入れると表示が揃わない
- **一意キーになる列が無い。** 認可保育所等一覧の `nursery_id` に当たるものが
  どのデータにも無い。実装時に `type` + `name` をキーにした（#186）。
  座標を混ぜると、市が座標だけ直したときに別施設として増えるため入れていない
- **児童館と公設公営児童クラブは17件が同一施設。** 両方入れると重複する。
  施設として1件にするか、種別を配列で持つかを決める必要がある
- **ファイルURLに日付が入るものがある。** `jidokan20260401.xlsx` /
  `kousetsukoueiclub2026.xlsx` / `202608_mineijidouclubmap.xlsx` /
  `chiikikosodateshiennkyotennR80601.xlsx` は更新のたびにURLが変わる。
  **固定URLを叩く cron は組めない。** 公開ページのHTMLからリンクを解決する
- **鮮度は `Last-Modified` で判定できる。** 全ファイルが返す。差分検知はこれで足りる

## 各 issue への波及

### #184（エリアページを周辺の子育て施設まで広げる）

- 使うのは **児童館・児童クラブ3種・地域子育て支援拠点・遊具のある公園**。
  私立幼稚園は鮮度確認後
- **公園の大字近似は不要**（座標がある）。市への公開依頼も不要
- 定期更新は **ページのHTMLからファイルURLを解決してから取得する**。
  固定URL前提の cron は日付入りファイル名で破綻する
- 出す情報は件数と直線距離まで、という方針は変えない

### #122（施設種別を増やすときのコレクション分割）

- 「`Nursery` に詰め込まない」は正しい。保育所固有の列は他のどのデータにも無い
- 一方、**今回追加する4種は列がほぼ共通**（名称・住所・電話・座標、＋対象小学校か
  実施日時）。種別ごとにコレクションを分けると、ほぼ同じスキーマが5本並ぶ。
  `facilities` 1コレクション＋`type` で足りる見込み。**`Nursery` とは分ける**
- 一意キーが無い件（上記）はここで決める

### #120（Atlas Search への切り替え）

- 追加後の規模は保育所119件＋施設約340件。**まだ正規表現のままで問題ない**。
  #120 の「数百件のうちは切り替えない」という判断の目安に収まる
- 切り替えを検討するのは、種別横断検索を1クエリで返したくなったとき

### #151 / #111 / #113（SEO・データ基準日・出典表記）

- 出典がデータセット単位で増える。`app/components/CreativeCommons.vue` は
  認可保育所等一覧だけを前提にしているので、複数ソース対応が要る（#113）
- `source_date` はソースごとに持つ必要がある（#111 の重要度が上がる）
- 施設の構造化データは `ChildCare` ではなく種別に合うもの（児童館なら
  `CommunityCenter`、公園なら `Park`）を選ぶ

## 再現手順

```bash
# 公開データセット一覧（407件）
curl -sSL -o opendata.html https://www.city.tsukuba.lg.jp/opendata/10060.html

# 実ファイルの更新日を見る
curl -sSI https://www.city.tsukuba.lg.jp/material/files/group/65/convalescence.xlsx | grep -i last-modified
```

xlsx は依存を足さなくても `unzip -p <file> xl/worksheets/sheet1.xml` と
`xl/sharedStrings.xml` を読めば列名と行数が分かる。

市の**保有データ一覧**（未公開のものも含む）は
https://www.city.tsukuba.lg.jp/material/files/group/21/tsukuba_datalist_2022.csv
（Shift_JIS）。ただし2022年時点の内容で、公開状況とはずれている。
