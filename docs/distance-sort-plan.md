# 距離順ソート 実装方針（#87）

作成日: 2026-08-19

対応Issue: [#87 距離順ソートを実装する](https://github.com/RyoheiTanaka/kosodate-portal/issues/87)

着手前の調査メモ。#87 の「検討事項」に挙がっていた3点（住所入力・距離の計算方法・サーバー/クライアント）
に対する結論と、Google Maps Platform の料金・GCP 側の操作をまとめる。

---

## 前提: 保育所側の座標は既にある

つくば市のオープンデータに緯度経度が含まれており、**119件すべてに `latitude` / `longitude` がある**。

したがってジオコーディングが必要なのは **利用者側の基準点だけ**。
保育所の住所を座標に変換する処理は一切要らない。#87 が「実装コストが低い」としているのはこのため。

---

## 1. 距離の計算: クライアント側 + Haversine

**結論: クライアント側で計算する。**

### サーバー側（`2dsphere` + `$near`）を採らない理由

#106 で一覧の絞り込みをクライアント側に一本化した。条件を変えるたびにサーバーへ往復する形に戻すと、
その判断と逆行する。並び替えだけサーバーに置くと、絞り込みとの合成もサーバー側に持っていく必要が出る。

119件の三角関数計算はブラウザで一瞬。件数が桁で増えたら（#112）そのとき考え直せばよい。

### 実装量の見込み

| 追加するもの | 目安 |
| --- | --- |
| Haversine の距離関数 | 15行程度 |
| `comparators` への追加 | 1行 |
| 現在地を扱う composable | 40行程度 |
| カードへの距離表示 | 10行程度 |

#110 で `comparators` を静的な定数表ではなく `computed` にしてあるため、
**現在地の ref を参照する比較関数を1つ足すだけ**で並び替えに載る。

### 距離の表示

- 1km未満は `約800m`、1km以上は `約1.2km`
- **直線距離であることを明示する。** 送迎の実際の道のりではない
- 経路距離（Directions API / Distance Matrix API）は初手では採らない。
  課金が発生するうえ、119件×移動手段の組み合わせでリクエスト数が跳ね上がる

## 2. 基準点の取り方: 3案

| 案 | 精度 | GCP | 費用 | #87 での扱い |
| --- | --- | --- | --- | --- |
| **A. Geolocation API**（ブラウザ） | 数十m | 不要 | 0円 | **本体で実装** |
| **B. 大字から選ぶ** | 大字単位 | 不要 | 0円 | **本体で実装**（Aのフォールバック） |
| **C. 住所を自由入力**（Geocoding API） | 番地単位 | 必要 | 月1万件まで無料 | **別issueに切る** |

### 案B の作り方

`scripts/data/oaza-district.json` に 72 大字がある。
既存の保育所座標から大字ごとの重心を出せば、追加データも外部APIも要らない。

大字に保育所が1件しかない場合は重心＝その園の座標になるが、基準点としては実用上問題ない。

### 案C を本体に含めない理由

GCP の操作と課金の有効化が必要になり、#87 の「コストが低い」という前提が崩れる。
A と B だけなら **GCP 操作ゼロ・費用ゼロ・クレジットカード登録も不要**で完結する。

これは #87 本文の「住所入力からの座標変換が必要かは要検討」への回答でもある。

## 3. 挙動（案A）

1. 並び替えの選択肢に「近い順」が増える
2. 選ぶとブラウザが位置情報の許可を求める
3. 許可 → 距離順に並び替え、各カードに `約1.2km` を表示
4. 拒否・取得失敗 → 「位置情報が使えません」と出し、案B（大字選択）へ誘導する
5. HTTPS が必須。localhost は例外として許可されるので開発時は問題なく、本番の Vercel は元々 HTTPS

### 注意点1: プライバシーポリシーの更新が要る

取得した座標はブラウザ内だけで使い、サーバーには送らない。
ただし `/privacy` には**位置情報に関する記載が現在まったく無い**（`app/pages/privacy/` を確認済み）。

「位置情報を取得すること」「取得した座標を送信も保存もしないこと」を明記する必要がある。

### 注意点2: URL に基準点を載せるべきではない

`?sort=distance` だけだと、共有された側では再度の許可が必要になる。
`?from=36.08,140.11` を載せれば再現できるが、**それは自宅の座標を URL に載せることになり、
共有した相手に自宅が知られる**。

**載せない方針を推す。** 共有先では「近い順」が選ばれた状態で、位置情報の許可を求めるところから始まる。

## 4. GCP 側の操作（案C を採る場合のみ）

### 現在のキーは流用できない

現在 `VITE_GOOGLE_MAPS_API_KEY` は Vite の `VITE_` 接頭辞によりクライアントへ露出している。
Maps Embed API はそれが前提の設計で、HTTP リファラ制限で守る。

一方 **Geocoding API のような Web Service API は HTTP リファラ制限が使えない**。
リファラ制限のキーで叩くとエラーになる。IP 制限が必要。

ところが Vercel の Hobby / Pro には固定 IP が無いため、IP 制限も使えない。

### 現実的な構成

1. GCP コンソールで **Geocoding API を有効化**
2. **サーバー専用のキーを新規発行する**（`VITE_` を付けない = クライアントに出さない）
3. アプリケーション制限は「なし」、**API 制限で Geocoding API のみに限定**
4. Nitro に `/api/geocode` を作り、そこからだけ呼ぶ。自前のレート制限を入れる
5. **Quotas で1日あたりの上限**と**予算アラート**を設定する（事故で青天井にしない）

キーを秘匿する以外の防御手段が無いため残存リスクがある。
この判断は [#90 DBのアクセス制御とAPIキー制限を確認する](https://github.com/RyoheiTanaka/kosodate-portal/issues/90) と一体で見る。

### 代替: 国土地理院の住所検索API

`https://msearch.gsi.go.jp/address-search/AddressSearch?q=...` で日本の住所を無料で引ける。
CORS も許可されておりブラウザから直接叩ける。

ただし **正式な API として提供されているかの確認が取れていない**。
地理院地図の内部 API を流用している形に見え、2015年に同じ問い合わせが
[gsi-cyberjapan/gsimaps#29](https://github.com/gsi-cyberjapan/gsimaps/issues/29) に出ているが、
公式回答は確認できなかった。

採用するなら国土地理院への確認が先。現時点では推奨に含めない。

## 5. 料金

2025年3月に **$200 の共通クレジットが廃止**され、API ごとの無料枠に変わった。無料枠は合算されない。

| API | 無料枠（月） | 超過後 |
| --- | --- | --- |
| **Maps Embed API**（現在使用中） | **Unlimited** | 課金なし |
| **Geocoding API** | **10,000件** | 1,000件あたり約 $5（大量利用で $4 に逓減） |

**現在このサイトが使っている地図表示は無制限無料**のため、Maps 関連の費用は現状ゼロ。

Geocoding が発火するのは「住所を入力して検索した回数」だけ。
月10,000件は1日あたり約330回にあたり、つくば市の保育所ポータルの規模で超える見込みは低い。
ただし **無料枠内でも課金の有効化とクレジットカード登録は必須**。

出典:

- [Google Maps Platform Pricing](https://developers.google.com/maps/billing-and-pricing/pricing)
- [Google Maps Platform security guidance](https://developers.google.com/maps/api-security-best-practices)
