# 保守モードの運用

機能拡張を終え、掲載情報の最新化を中心とした保守に移行した後の運用手順。

保守モードで問題になるのは新機能ではなく、**誰も触らないうちに静かに壊れるもの**。
放置期間が長いほど、久しぶりに触ったときの切り分けコストが上がる。
この文書は「何を、どの頻度で見るか」を固定して、そのコストを下げるために置いている。

---

## 月1回のメンテ枠

実施日: **毎月第1土曜**（目安）

1. **Dependabot PR をまとめて処理する**
   `dependabot` skill に手順がある。lockfile の修復は
   `.github/workflows/dependabot-lockfile.yml` が自動で行う
2. **サイトを目視確認する**
   - `/` トップページ
   - **`/nurseries` 一覧** ← 後述の理由により必須
   - 詳細ページを1件（地図が表示されるか）
   - `/contact` フォームが表示されるか
3. **Atlas からのメールが届いていないか確認する**

### `/nurseries` を必ず開く理由

MongoDB Atlas の Free (M0) クラスタは、**接続がゼロの状態が30日続くと自動的に一時停止される**。
再開は手動で、自動では戻らない。

このサイトで DB に接続するのは `/nurseries` 系のページだけ。
トップページや問い合わせページは接続を発生させない。
CI も同様で、スモークテスト（`scripts/ci-smoke.sh`）は DB を使うページを対象外にしている。

つまり **この月1回の目視確認が、唯一の定期的な接続機会**になっている。

- 30日枠に対して月1回はほぼ余裕がない。**2か月飛ばすと停止する**
- 停止の7日前と停止後に Atlas からメールが届く。これが実質の予告アラート
- 通知先は Atlas アカウントのメールアドレス（Project Owner 宛）

## 長く放置した後に再開するとき

「元から壊れていたのか、今回の変更で壊したのか」を切り分けるため、
コードを触る前に上から順に確認する。

1. Atlas のクラスタが paused になっていないか（なっていれば手動で resume）
2. `npm ci` が通るか
3. CI（`.github/workflows/ci.yml`）が `main` で緑か
4. 本番サイトが表示されるか

ここまで緑なら、以降の不具合は自分の変更が原因と判断してよい。

## 構成の前提（2026-08-19 時点）

保守中に判断を誤らないための、確認済みの前提。

| 項目 | 状態 |
| --- | --- |
| Atlas のティア | Free (M0)。30日で自動停止する |
| 本番DB `kosodate` への接続 | **読み取り専用ユーザー**。アプリは参照しかしない |
| 開発DB `kosodate_dev` | 開発用ユーザーが担当。本番には権限が及ばない |
| 本番へのデータ取り込み | 専用ユーザー `kosodate-import`（`readWrite@kosodate`） |
| Atlas の Network Access | 全開放。Vercel に固定IPが無いため許容し、権限分離で守る |
| Google Maps APIキー | **Maps Embed API のみ**に制限。リファラー制限あり |
| クライアントに露出する値 | `VITE_GOOGLE_MAPS_API_KEY` と `VITE_GOOGLE_RECAPTCHA_SITE_KEY` の2つだけ。`runtimeConfig.public` に機密値は無い |

## 触るときに壊してはいけない前提

- **Maps APIキーに Geocoding API を足さない。**
  Maps Embed API は無料・無制限だが、Geocoding は課金対象で、
  かつ HTTP リファラー制限が使えない。
  住所の自由入力（#139）に着手するときは**別のキーを新規発行する**
- **Maps APIキーの「APIの制限」を Embed 以外に広げない。**
  この制限が、キーが露出していても課金が発生しない根拠になっている
- **Maps Embed API に日次の割り当て上限を設定しない。**
  無料・無制限なので課金防御の効果は無く、アクセスが伸びたときに
  自分のサイトの地図が出なくなるだけになる
- **本番への取り込みに管理者ユーザーを使わない。**
  `kosodate-import` を使う。管理者ユーザーはコンソール作業と緊急時の退避用に残してある
