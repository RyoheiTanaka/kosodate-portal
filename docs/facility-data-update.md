# 子育て施設データの取り込み

認可保育所**以外**の子育て施設（`facilities` コレクション）の取り込み手順。
保育所は別のデータソース・別の手順なので [nursery-data-update-plan.md](nursery-data-update-plan.md) を見ること。

どのデータセットを採用して、どれを採用しなかったかは
[opendata-survey.md](opendata-survey.md) にある。

---

## 実行

```bash
# 全種別の差分を確認する（書き込まない）
npm run import:facilities -- --type=all --dry-run

# 全種別を開発用DBに取り込む
npm run import:facilities -- --type=all

# 本番DBに取り込む
MONGODB_DB=kosodate npm run import:facilities -- --type=all --prod
```

`--type=` で施設種別を選ぶ（既定は `jidokan`、`all` で全種別）。対応している種別は
`scripts/import-facilities.mjs` の `DATASETS` にある。

**`--type=all` は定義順に流れる。** 児童クラブは併設先の児童館を先に必要とするため、
順番には意味がある（後述）。個別に流すときも児童館を先にすること。

## 保育所の取り込みと違うところ

### CSVを手で用意しない

保育所は Excel から書き出した CSV（`scripts/data/nurseries-2026.csv`）をリポジトリに
置いているが、施設側は**実行のたびに市のサイトから xlsx を取りに行く**。

- 種別が増えるとファイルも増え、手で書き出す運用が続かない
- xlsx を読む手段がある（`scripts/lib/xlsx.mjs`。依存は足していない）

### ファイルURLを決め打ちにしていない

`jidokan20260401.xlsx` のように**ファイル名に日付が入るデータセットがある**。
更新のたびにURLごと変わるので、固定URLを叩くと 404 になるか、古いファイルを掴み続ける。

公開ページ（ページIDのURL）は変わらないので、そこのHTMLから
`/material/files/` へのリンクを解決してから取得している。

そのため、**市がページの構成を変えると取り込みが止まる**。
「ファイルがありません」「複数当たりました」で落ちた場合は、
`DATASETS` の `sourceUrl` と `pattern` を確認する。

### 鮮度を警告する

市の「更新周期: 随時」は実態と合わないことがある（病児・病後児保育の xlsx は
3年以上更新されておらず、ページと電話番号が食い違っていた）。

取得したファイルの `Last-Modified` を表示し、**2年以上更新されていない場合は警告を出す**。
警告が出たら、市のページと突き合わせてから取り込むこと。

### 一意キーが無い

市が振った番号（保育所の `nursery_id` に当たるもの）がどのデータセットにも無いため、
**`type` + `name`** を upsert のキーにしている。

- 座標をキーに混ぜていない。市が座標だけ直したときに、別施設として増えてしまうため
- **施設名が変わると「新規 + 一覧から消えた」として出る。** 改称と閉館の区別が付かないので、
  「一覧から消えた」が出たら市のページを確認する

### 同じ建物を2件にしない（併設の統合）

**公設公営児童クラブ31件のうち17件は児童館そのもの**で、名称・住所・電話・座標が
児童館一覧と一致する。別ドキュメントにすると同じ建物が2件になり、
「周辺に子育て施設が何件」を数えたときに二重に数えてしまう。

そこで児童クラブの取り込みでは、**名称が一致する児童館があれば、そちらへ
併設情報（`attributes.区分` と `attributes.受入対象小学校`）として書き込み、
児童クラブ側のドキュメントは作らない**。

そのため:

- **児童館を先に取り込む必要がある。** 併設先が1件も無ければエラーで止まる
- **小学校区から児童クラブを引くときは、`jidokan` と `jidou-club` の両方を見る。**
  17件ぶんの `受入対象小学校` は児童館のドキュメントに乗っている
- 名称が一致しても座標が100m以上離れていれば、同名の別施設として独立させる（警告が出る）

`attributes` は**キー単位（ドット記法）で書き込んでいる**。オブジェクトごと `$set` すると、
児童館を単独で取り込み直したときに、児童クラブ側が足したキーが消えるため。

### 施設種別をまたぐ重複は残している

出張子育て広場は「会場」なので、他の施設と同じ場所に立つことがある
（例: 研究学園小学校児童クラブは `jidou-club` と `kosodate-shien` の両方にある）。

これは統合していない。開催日時を持つ「広場」と、放課後を過ごす「児童クラブ」は
別のものとして探されるため。**エリアページで件数を出すときは、
合計1つの数字にせず種別ごとに分けて出すこと**（同じ建物を1件と数えるか2件と数えるかを
考えなくて済む）。

## 新しい大字が出たとき

施設は保育所が無い大字にも建っている。エリアを判定できない大字が出ると
**取り込みが止まる**（空のまま入れるとエリア絞り込みから消えるため）。

`scripts/data/oaza-area.json` と `scripts/data/oaza-district.json` の**両方**に追記する。
大字マップは保育所の取り込みと共用している（`scripts/lib/oaza.mjs`）。

エリアは市の区分ではなくこのサイト独自の軸なので、機械的には決まらない。
`app/data/oaza-latlng.json`（大字の代表点）で近い大字を見て、そのエリアに寄せる。
地区は市の公式区分なので推測しない。
[地域・年齢別人口](https://www.city.tsukuba.lg.jp/1005656/1005680.html) の CSV にある
地域コードが旧町村ごとの連番になっていて（3xx 谷田部 / 5xx 桜 / 6xx 大穂 / 7xx 豊里 /
8xx 筑波 / 9xx 茎崎）、おおよそこれで判断できる。

ただし**例外がある**。稲岡は 393 で谷田部の連番に入っているが、市の認可保育所等一覧では
茎崎地区になっている。番号は目安で、**市が地区を明記しているデータがあればそちらが正**。

追加済みの大字と、判断が入っているもの:

| 取り込み | 追加した大字 |
| --- | --- |
| 児童館 | 横町・小茎・東 |
| 児童クラブ / 支援拠点 | 上岩崎・柳橋・境田・みどりの南・栗原・館野・前野・緑が丘・山口・万博公園西・玉取・栄・梅園・小白硲・山中 |

- **東**（谷田部地区・南部エリア）— 地区と生活圏がずれる例。並木の東隣なのでエリアは南部
- **梅園**（桜地区・南部エリア）— 竹園と並木の間。並木が0.7kmで竹園より近いので南部
- **小白硲**（谷田部地区・みどりのエリア）— 上横場1.5km と水堀1.7km の間。僅差
- **万博公園西** — 「つくば市万博公園西Ｆ30-1」のように大字の後ろに街区の記号が付く。
  `toOaza()` は末尾の英字を落として「万博公園西」として引く
