# 子育て施設データの取り込み

認可保育所**以外**の子育て施設（`facilities` コレクション）の取り込み手順。
保育所は別のデータソース・別の手順なので [nursery-data-update-plan.md](nursery-data-update-plan.md) を見ること。

どのデータセットを採用して、どれを採用しなかったかは
[opendata-survey.md](opendata-survey.md) にある。

---

## 実行

```bash
# 差分を確認する（書き込まない）
npm run import:facilities -- --dry-run

# 開発用DBに取り込む
npm run import:facilities

# 本番DBに取り込む
MONGODB_DB=kosodate npm run import:facilities -- --prod
```

`--type=` で施設種別を選ぶ（既定は `jidokan`）。対応している種別は
`scripts/import-facilities.mjs` の `DATASETS` にある。

## 保育所の取り込みと違うところ

### CSVを手で用意しない

保育所は Excel から書き出した CSV（`scripts/data/nurseries-2026.csv`）をリポジトリに
置いているが、施設側は**実行のたびに市のサイトから xlsx を取りに行く**。

- 種別が増えるとファイルも増え、手で書き出す運用が続かない
- xlsx を読む手段がある（`scripts/lib/xlsx.mjs`。依存は足していない）

### ファイルURLを決め打ちにしていない

`jidokan20260401.xlsx` のように**ファイル名に日付が入るデータセットがある**。
更新のたびにURLごと変わるので、固定URLを叩くと 404 になるか、古いファイルを掴み続ける。

公開ページ（ページIDのURL）は変わらないので、そこのHTMLから
`/material/files/` へのリンクを解決してから取得している。

そのため、**市がページの構成を変えると取り込みが止まる**。
「ファイルがありません」「複数当たりました」で落ちた場合は、
`DATASETS` の `sourceUrl` と `pattern` を確認する。

### 鮮度を警告する

市の「更新周期: 随時」は実態と合わないことがある（病児・病後児保育の xlsx は
3年以上更新されておらず、ページと電話番号が食い違っていた）。

取得したファイルの `Last-Modified` を表示し、**2年以上更新されていない場合は警告を出す**。
警告が出たら、市のページと突き合わせてから取り込むこと。

### 一意キーが無い

市が振った番号（保育所の `nursery_id` に当たるもの）がどのデータセットにも無いため、
**`type` + `name`** を upsert のキーにしている。

- 座標をキーに混ぜていない。市が座標だけ直したときに、別施設として増えてしまうため
- **施設名が変わると「新規 + 一覧から消えた」として出る。** 改称と閉館の区別が付かないので、
  「一覧から消えた」が出たら市のページを確認する

## 新しい大字が出たとき

施設は保育所が無い大字にも建っている。エリアを判定できない大字が出ると
**取り込みが止まる**（空のまま入れるとエリア絞り込みから消えるため）。

`scripts/data/oaza-area.json` と `scripts/data/oaza-district.json` の**両方**に追記する。
大字マップは保育所の取り込みと共用している（`scripts/lib/oaza.mjs`）。

エリアは市の区分ではなくこのサイト独自の軸なので、機械的には決まらない。
`app/data/oaza-latlng.json`（大字の代表点）で近い大字を見て、そのエリアに寄せる。
地区は市の公式区分なので推測しない。
[地域・年齢別人口](https://www.city.tsukuba.lg.jp/1005656/1005680.html) の CSV にある
地域コードが旧町村ごとの連番になっていて（3xx 谷田部 / 5xx 桜 / 6xx 大穂 / 7xx 豊里 /
8xx 筑波 / 9xx 茎崎）、これで確認できる。

児童館の取り込み時に追加したのは、横町（桜地区・桜エリア）・小茎（茎崎地区・南部）・
東（谷田部地区・南部）の3つ。東は地区と生活圏がずれる例で、
地区は谷田部だが並木の東隣なのでエリアは南部にしている。
